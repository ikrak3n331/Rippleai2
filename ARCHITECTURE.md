# Architecture & Design

## Overview

Nine complete pages built from the Ripple 2.0 Extended design system (Victorian Government SDP / Salesforce section). The build uses **Vite with an HTML include plugin**, so the banner, footer, and icon sprite exist once and are injected into every page at build time.

## The Include Plugin

**File:** `vite.config.js`, function `includePartials()`

How it works:
1. During dev (`npm run dev`) and build (`npm run build`), Vite's `transformIndexHtml` hook intercepts HTML
2. Any line matching `<!--#include partials/XXX.html -->` is replaced with the contents of that file
3. Nesting is supported one level deep (if a partial includes another, it's resolved once)
4. HMR watches the `partials/` directory, so editing a partial hot-reloads all pages

This means:
- **One banner**, used in all 9 pages — edit `partials/banner.html` once
- **One footer**, used in all 9 pages — edit `partials/footer.html` once
- **One sprite**, used in all 9 pages — edit `partials/sprite.html` once
- No duplication, no sync issues

## The Password Gate

`partials/gate.html` is included in the `<head>` of every page except
`pages/password.html`. It is a plain blocking `<script>` rather than a module,
so a locked page never paints before the redirect fires. It looks for the
`ripple-unlocked` session flag and, without it, sends the visitor to
`pages/password.html?next=<the path they asked for>`.

`src/password.js` holds the password, sets the flag on a match and returns the
visitor to `next` — same-origin paths only, so the parameter cannot be turned
into an open redirect. The flag lives in `localStorage`, so the password is
asked for once per browser: a link opened in a new tab does not reliably
inherit session storage, and the index links open in new tabs. Clearing site
data locks it again.

This is a curtain, not a lock: the site is static, the password ships in the
bundle, and anyone who opens devtools can read it. It keeps the examples out of
casual view and nothing more. Real protection has to come from the host (HTTP
basic auth, an access-controlled deploy).

## CSS Architecture

**`src/styles.css` (~850 lines)**
- @font-face rules for VIC (all 4 weights)
- CSS custom properties for Ripple tokens (colours, fonts, layout constants)
- Utility classes (skip-link, icon, sprite)
- Component-level styles specific to the Privacy Page (banner, progress rail, page shell, form, accordion, footer)
- Mobile-first, five breakpoints: 320 / 992 / 1200 / 1600 / 1920

**`src/components.css` (~600 lines)**
- Shared component styles used across multiple pages
- Hero sections, introduction banners, cards, form controls, tabs, login page, component gallery
- All responsive, all tied to Ripple tokens defined in styles.css

Both files are imported in the page `<head>`:
```html
<link rel="stylesheet" href="/src/styles.css">
```

(The import of components.css happens inside styles.css: `@import "./components.css";`)

## JavaScript Behaviour

**`src/main.js`**

Four vanilla JS modules, no dependencies:

1. **Banner menu** — click to open/close dropdown, Escape to close, click-outside to dismiss
2. **Accordion** — individual items toggle open/closed, "Open all"/"Close all" button synchronizes all
3. **Tabs** — click to select, arrow keys (Left/Right/Home/End) per WAI-ARIA pattern
4. **Textarea word count** — live count updates as user types (via data-word-count attribute)

All modules use `data-*` attributes for configuration:
- `[data-accordion]` — root accordion container
- `[data-accordion-toggle]` — the "Open all" button
- `[data-tabs]` — root tabs container
- `[data-word-count="id"]` — textarea with output element ID

## Figma Connection

**No bi-directional sync.** The pages are built from Figma node data (read-only):

- Node data extracted via `.fig` file decoding (ZIP + Zstandard + Kiwi format)
- Colours resolved through Ripple library's shared styles (so they carry token names, not raw hex)
- Vector geometry for icons/logo decoded from path blobs into SVG
- Placeholder imagery extracted from the archive and re-encoded to WebP
- All measurements (widths, heights, gaps, padding) read from node coordinates and auto-layout specs

**To update a page:** edit the HTML files in `pages/` directly. To update the entire design system, regenerate from the Figma file using the decoder tools (see REBUILD.md).

## Breakpoints & Responsive Behaviour

All pages are mobile-first, responsive across five breakpoints:

| Viewport | Context |
| --- | --- |
| 320–991px | Mobile layout (single column, no progress rail) |
| 992–1199px | Tablet/small desktop (progress rail visible, 992px footer variant) |
| 1200–1599px | Desktop (progress rail + form container, standard footer) |
| 1600–1919px | Wide desktop (expanded grey panel, 1600px variant) |
| 1920px+ | Ultra-wide (expanded grey panel, 1920px variant) |

Media query breakpoints in CSS:
- `@media (min-width: 992px)` — desktop layout, progress column
- `@media (min-width: 1200px)` — full form width, standard footer
- `@media (min-width: 1600px)` — expanded panel widths

## Accessibility

- All interactive elements use semantic HTML (`<button>`, `<a>`, `<input>`, `<select>`, `<textarea>`, `<fieldset>`)
- ARIA attributes manage state: `aria-expanded`, `aria-selected`, `aria-controls`, `aria-labelledby`
- Skip link to main content (`.skip-link`)
- Focus management: banner menu focuses button on Escape, tabs manage focus per WAI-ARIA pattern
- Live region for word count: `aria-live="polite"`
- Form labels linked via `for`/`id`
- Colour not the only differentiator

## Performance

**Production build output:**
- 9 HTML pages (22–29 KB each)
- 1 CSS bundle (22.7 KB, 4.9 KB gzipped)
- 1 JS bundle (2.8 KB, 1.1 KB gzipped)
- 4 font files (21–22 KB each, WOFF2)
- 2 images (40 KB hero, 22 KB cards)

Total: ~380 KB uncompressed, ~100 KB gzipped (before network compression).

No JavaScript framework overhead, no runtime CSS-in-JS, no unused CSS.

## Multi-Page Routing

Vite's `rollupOptions.input` in `vite.config.js` specifies all entry points:

```javascript
input: { 
  index: resolve(root, 'index.html'),
  privacy: resolve(root, 'pages/privacy.html'),
  // ... etc for all 8 pages
}
```

Each page is built as a separate HTML file with its own CSS and JS bundles (Vite deduplicates shared code automatically).
